Legenda Penanda Kolom

PK Primary Key FK Foreign Key UQ Unique IDX Index NULL Boleh kosong SOFT Soft delete

Aksi saat induk dihapus: cascade ikut terhapus · restrict tidak boleh dihapus · set null kolom dikosongkan.

Alur Utama Sistem

1 Standarisasi Ukuran

body_measurements→ size_charts→ size_chart_entries→ size_chart_entry_measurements

Admin mendefinisikan dimensi ukur (lingkar dada, panjang kaki, dst), lalu membuat standar resmi FitMate. Di tabel terakhir dijawab pertanyaan "XL itu berapa?" — misal XL = lingkar dada 104–108 cm. Toko tidak boleh membuat definisi sendiri.

2 Profil Badan Pengguna

users→ user_body_profiles→ user_body_measurements

Satu user bisa punya beberapa profil badan (diri sendiri, pasangan, adik). Angka ukurannya diisi sekali, lalu berlaku di semua toko.

3 Rekomendasi Ukuran

user_body_measurements+ size_chart_entry_measurements→ size_recommendations

Ukuran badan user dibandingkan dengan rentang tiap label ukuran. Label dengan kecocokan terbanyak jadi rekomendasi, lengkap dengan fit_score dan status tight / fit / loose. Hasilnya disimpan sebagai cache.

4 Katalog Produk

stores→ products→ product_variants→ product_measurements

Produk milik toko, varian menyimpan kombinasi ukuran + warna beserta stoknya. Ukuran varian menunjuk ke size_chart_entries, bukan teks bebas. Ukuran fisik barang diisi seller untuk diverifikasi admin.

5 Checkout Multi-Toko

carts→ orders→ store_orders→ order_items

Keranjang boleh berisi barang dari banyak toko. Saat checkout: satu order (satu kali bayar) dipecah menjadi beberapa store_order yang statusnya jalan sendiri-sendiri, karena tiap toko mengirim terpisah.

6 Umpan Balik & Koreksi

order_items→ product_reviews→ size_charts

Review menyimpan fit_feedback (kekecilan / pas / kebesaran). Kalau banyak yang mengeluh ukuran tertentu meleset, admin punya bukti untuk menyetel ulang rentang standarnya.

Catatan Desain Penting

Satu standar ukuran untuk semua toko

Seller tidak membuat size chart sendiri. Mereka hanya memilih label yang sudah ada di size_chart_entries, sehingga 'XL' bernilai sama persis di seluruh marketplace.

Data transaksi disalin, bukan direferensi

Alamat di orders dan detail produk di order_items disimpan sebagai salinan. Nota lama tetap benar walau produk dihapus atau harga berubah.

Satu bayar, banyak toko

payments menempel di orders, sedangkan shipments menempel di store_orders. User bayar sekali, tapi tiap toko punya resi dan status kirim sendiri.

Soft delete di tempat kritis

stores dan products memakai soft delete supaya riwayat order lama tidak kehilangan referensinya.

Kamus dimensi bisa tumbuh tanpa migration

Dimensi ukur baru cukup ditambahkan sebagai baris di body_measurements. Semua tabel ukuran mengikutinya lewat foreign key.

Rekomendasi disimpan sebagai cache

size_recommendations menyimpan hasil hitung agar tidak dihitung ulang tiap kali produk dibuka, sekaligus jadi bahan analitik akurasi rekomendasi.

FitMate — dokumentasi skema database dari database/migrations.
